# Upstream bug and support audit

Audit date: 22 October 2026. Baseline commit: `b856a45e684775fd477dbcd8d1342ff65bb97e38`, Firemote `v4.1.9`. Implementation belongs only to `Narehood/HomeAssistant-TV-Remote`; upstream access is read-only. See the [modernization plan](MODERNIZATION_PLAN.md).

## Coverage

Upstream: https://github.com/PRProd/HA-Firemote/issues?q=is%3Aissue%20state%3Aopen . REST GET https://api.github.com/repos/PRProd/HA-Firemote/issues?state=open&per_page=100 returned all three pages: 100 + 100 + 8 records = 208, of which 19 are PRs and **189 are open issues**. Independent GET and shared .git/audit/upstream-open-issues.json contain identical sets of 189 issue numbers. GitHub connector search capped at 100, so GET pagination established completeness. All titles/labels and candidate bodies were read; material issue comments were fetched by connector, with GET fallback for failed closed #525. All 124 New App Shortcut and 7 App Shortcut Update entries were screened for hidden failure reports.

The matrix has **39 groups covering 45 distinct open issue numbers**, including feature-labeled issues that describe current behavior/support gaps. The feature table cites 23 distinct open issue numbers, 5 already in the matrix, leaving 18 additional high-impact non-app requests.

Disposition key: **code confirmed** means local source matches the reported mechanism, not that hardware was run. **Device validation** means package, activity, service, CEC, IR, or app response cannot be established from static code. Unbroken catalog requests are outside the bug matrix. The issue #735 device request is included because it reports failed event modes.

## Additional defects found in the code audit

These are source-level repair tasks in addition to the upstream issue matrix. They do not increase the count of upstream reports. Detailed evidence and VM reproductions are in the [architecture audit](ARCHITECTURE_AUDIT.md).

| Finding | Repair and acceptance |
| --- | --- |
| A1 Input lifecycle | Cancel repeats and release held keys on cancellation, loss of capture, blur, or disconnect; remove listeners after each interaction. |
| A2 Configured markup | Render labels, URLs, icons, and styles without concatenating configuration into parsed HTML; punctuation cannot introduce new attributes or elements. |
| A3 ADB text quoting | Prevent shell expansion and additional commands; verify quotes, dollar signs, backticks, backslashes, spaces, and newlines. |
| A4 Keyboard and hidden controls | Core controls execute exactly once through keyboard activation and have accessible names; hidden controls cannot receive focus or dispatch. |
| A5 State and override normalization | A missing configured remote gives a recoverable status instead of throwing during rendering; meaningful `false` and `0` device overrides retain their values. |
| A6 Editor mutation | Rendering the editor must not mutate the caller's configuration or silently delete associations; all selector values must match their associated fields. |
| A7 Numeric normalization | Numeric `0` and quoted `"0"` must produce identical launcher dimensions; preserve documented quoted scale values. |
| A8 Dispatch and identity | Stop Apple mute falling through to ADB; support accepted singleton custom actions and names containing `-button`; align Homatics capacities; fix Toshiba matching; preserve documented `restart-button` behavior with an alias. |
| A11 Incomplete catalog coverage | Every advertised family has a complete launch strategy or an explicit unsupported result; cover the Pathé Thuis gaps and validate all entries. |
